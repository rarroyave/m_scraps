\section{m\_scraps: project overview}\label{m_scraps-project-overview}

This document describes (a) what SCRAPS is, (b) what was extended in
this fork, and (c) how to use the resulting tool. It is meant as a
technical map of the codebase for a new collaborator or for our future
selves. For installation and quick-start usage see the top-level
\texttt{README.md}; for benchmarks against ATAT mcsqs see
\texttt{docs/mcsqs\_comparison.md}.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{1. What SCRAPS is}\label{what-scraps-is}

SCRAPS --- \textbf{S}uper\textbf{C}ell \textbf{R}andom
\textbf{AP}proximate\textbf{s} --- is a combinatorial-optimization code
for generating special quasi-random structures (SQS) and
short-range-ordered (SRO) supercells of multicomponent alloys. The
upstream version was developed at Iowa State by Rahul Singh, Prashant
Singh, Aayush Sharma, Ganesh Balasubramanian, and Duane D. Johnson, and
is published in:

\begin{quote}
R. Singh et al., \emph{Nature Computational Science} \textbf{1}, 54
(2021). DOI: 10.1038/s43588-020-00006-7
\end{quote}

The upstream repository is
\href{https://github.com/DuaneDJohnson/Hybrid-Cuckoo-Search}{\texttt{DuaneDJohnson/Hybrid-Cuckoo-Search}}.
The MIT license has been preserved with dual copyright (Iowa State +
Arroyave fork).

\subsubsection{1.1 The Warren--Cowley
formulation}\label{the-warrencowley-formulation}

For a multicomponent alloy on a single sublattice, the Warren--Cowley
short-range-order parameter is

\[\alpha_{ij}^{(k)} = 1 - \frac{P(j \mid i, k)}{c_j}\]

where \(P(j \mid i, k)\) is the conditional probability that the
neighbor of an atom of species \(i\) at the \(k\)-th coordination shell
is of species \(j\), and \(c_j\) is the bulk concentration of species
\(j\). The ``random'' limit (an exact SQS) has \(\alpha_{ij}^{(k)} = 0\)
for all \((i, j, k)\). Ordered structures (B2, L1₂, etc.) have
characteristic non-zero \(\alpha\) signatures at specific shells.

SCRAPS' loss function on a candidate supercell is

\[E = \sum_{k=1}^{K_\mathrm{max}} w_k \sum_{i \neq j} \big( N_{ij}^{(k)} - T_{ij}^{(k)} \big)^2\]

where \(N_{ij}^{(k)}\) is the actual count of \((i, j)\) pairs at shell
\(k\) in the candidate and

\[T_{ij}^{(k)} = N_i \cdot (1 - \alpha_{ij}^{(k),\,\mathrm{target}}) \cdot z_k \cdot N_j / N\]

is the target. The fitness reported in the log is \(\sqrt{E}\).

\subsubsection{1.2 The Hybrid Cuckoo
Search}\label{the-hybrid-cuckoo-search}

SCRAPS minimizes \(E\) over the discrete space of atomic arrangements
using a metaheuristic combining:

\begin{itemize}
\tightlist
\item
  \textbf{A population of ``nests''} (candidate supercells), each
  independently evolving through MC swap moves (\texttt{empty\_nests}).
\item
  \textbf{A ``cuckoo'' step} that probabilistically replaces low-fitness
  nests with new randomized ones (\texttt{get\_cuckoos}), giving the
  search a way to escape local minima.
\item
  \textbf{Global ranking} across MPI ranks at the end
  (\texttt{get\_best\_nest} plus the merge step in \texttt{main}).
\end{itemize}

Per-rank MC swap moves are: pick two atom positions, swap their species,
evaluate fitness, accept if it improved (with a small
\(\varepsilon\)-band stochastic acceptance to allow neutral moves).

\subsubsection{1.3 Original assumptions and
limitations}\label{original-assumptions-and-limitations}

\begin{itemize}
\tightlist
\item
  Single sublattice with uniform per-shell coordination.
\item
  A \textbf{single scalar \(\alpha\) target} applied to every species
  pair at every shell (no per-pair targeting).
\item
  POSCAR + INPUT file format (a SCRAPS-specific dialect of VASP POSCAR
  with no species labels, plus a custom INPUT keyword block).
\item
  MPI-parallel over nest population; no shared memory inside a rank.
\end{itemize}

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

fixes}\label{what-m_scraps-adds-and-fixes}

targets), spectator-sublattice support for HEB-class structures,
user-facing heuristics, an algorithmic upgrade (delta-fitness MC), a
reproducibility layer, and a Python-side tool suite.

\subsubsection{2.2 The headline feature: per-pair SRO
targets}\label{the-headline-feature-per-pair-sro-targets}

New INPUT keyword:

\begin{verbatim}
SRO  <species_i>  <species_j>  <shell_index>  <alpha_target>
\end{verbatim}

Sets \(\alpha_{ij}^{(k)\,\mathrm{target}}\) for one \((i, j, k)\)
triple. Lines may repeat; entries are automatically symmetrized
\(\alpha_{ji} = \alpha_{ij}\). Pairs not mentioned default to
\(\alpha = 0\) (the SQS target).

The targetSROpair tensor is threaded through \texttt{fitnessvalue},
\texttt{fitnessofnests}, \texttt{get\_best\_nest},
\texttt{empty\_nests}, \texttt{empty\_nests\_fast},
\texttt{get\_cuckoos}, and \texttt{main}. Upstream only supported a
single scalar \(\alpha\) applied uniformly; this fork lets each species
pair at each shell have its own target.

This is what makes targeting \textbf{classical ordered structures} in a
single SCRAPS run possible. See
\texttt{tests/\{b2\_bcc\_binary,l12\_fcc\_a3b,\ l10\_fcc\_ab,d03\_bcc\_a3b,l11\_fcc\_ab,l21\_bcc\_x2yz\}/}
for the six worked cases (B2, L1₂, L1₀, D0₃, L1₁, L2₁/Heusler).

\subsubsection{2.3 Spectator sublattice (HEB-class
structures)}\label{spectator-sublattice-heb-class-structures}

For structures like AlB₂-type (Hf,Zr,Ti,Ta,Nb)B₂ high-entropy diborides,
one sublattice is compositionally fixed (boron) and the other carries
the chemical disorder. New INPUT keyword:

\begin{verbatim}
SPECTATOR_BASIS_SPECIES  <basis_index>  <species_index>
\end{verbatim}

declares that all atoms at the given POSCAR basis position are fixed at
the given species and not touched by MC. The fitness function becomes
``M-sublattice only'' --- pairs involving a spectator atom are excluded,
the reference concentration becomes \(N_j^M / N^M\), and the effective
coordination is the count of non-spectator neighbors per non-spectator
atom.

A coordination check (\texttt{Lattice::coordination\_per\_shell}) is run
at startup on the non-spectator subset; if it's non-uniform, SCRAPS
aborts with a diagnostic pointing to ATAT mcsqs for the truly
multi-sublattice cases SCRAPS can't handle.

See \texttt{tests/heb\_5metal\_random/} and
\texttt{tests/heb\_5metal\_csro/} for worked HEB cases.

\subsubsection{2.5 Algorithmic upgrades}\label{algorithmic-upgrades}

\textbf{Delta-fitness MC (\texttt{empty\_nests\_fast}, default on).} The
legacy \texttt{empty\_nests} recomputed the full \(O(N \cdot z)\)
fitness on every swap proposal. The fast path precomputes the constant
target matrix \(T_{ij}^{(k)}\) once per nest, maintains the pair-count
tensor \(N_{ij}^{(k)}\) as state, and applies an \(O(z)\) delta per swap
(touching only the neighbors of the two swapped atoms; the swapped pair
itself contributes zero net delta by symmetry). On RNG-pinned A/B tests
against the legacy path, this yields \textbf{2--18× speedup on
loop-bound cases} with identical final fitness:

\begin{longtable}[]{@{}llll@{}}
\toprule\noalign{}
Case & Legacy wall & Fast wall & Speedup \\
\midrule\noalign{}
\endhead
\bottomrule\noalign{}
\endlastfoot
25:50:25 n=108 (plateau) & 15.2 s & 0.8 s & 18.6× \\
25:50:25 n=256 & 3.1 s & 0.4 s & 8.2× \\
BCC 50:50 n=54 & 4.8 s & 0.6 s & 7.4× \\
\end{longtable}

\textbf{Targeted swap proposals (\texttt{empty\_nests\_fast}, off by
default).} With probability \texttt{TARGETED\_SWAP\_PROB}, propose swaps
biased toward the species pair \((i, j, k)\) with the largest weighted
residual². The remaining fraction stays uniform-random for exploration.
\textbf{Honest finding from our benchmarks: on the test cases we
measured (cell sizes up to n=500, B2 / L1₂ / L1₀ / D0₃ / L1₁ ordered
targets, infeasibility plateaus), uniform-random already converges fast
enough that the bias adds overhead without speedup.} Kept as an opt-in
for workloads where uniform random would genuinely struggle (very large
supercells, complex multi-pair SRO, highly non-convex landscapes) and as
a starting point for further algorithmic experimentation.

\subsubsection{2.6 Feasibility check (the ``is fitness=0 even
achievable?''
math)}\label{feasibility-check-the-is-fitness0-even-achievable-math}

For an SQS target (\(\alpha = 0\)), the expected pair count
\(T_{ij}^{(k)} = N_i \cdot z_k \cdot N_j / N\) must be \textbf{integer}
for every weighted shell-pair. If it isn't, the fitness has a strictly
positive lower bound --- the optimizer plateaus at a non-zero value no
matter how long it runs.

This caught us by surprise during the cell-size benchmark: 25:50:25 on
FCC \texttt{k×k×k} is feasible for \texttt{k} even and infeasible for
\texttt{k} odd (at shell 1, \(T_{AC} = 3k^2/2\)), explaining the
deterministic \texttt{fitness\ =\ √2.5\ \ approximately\ \ 1.58} plateau
at n=108 and n=500.

\texttt{tools/suggest\_cell.py} walks candidate cell sizes (including
non-cubic supercells) and returns the closest feasible
\texttt{Cell\_DIM}, plus the fitness floor for infeasible candidates. It
handles HEB-style spectator sublattices via the same \texttt{M}-only
math SCRAPS uses internally. The C++ runtime also runs the feasibility
check at startup and prints a warning naming the offending pair(s) when
the configured \texttt{(ELEMENT,\ Cell\_DIM,\ MAXSHELLNUM)} is
infeasible.

\subsubsection{2.7 Multi-sublattice SQS (the v0.4.0
headline)}\label{multi-sublattice-sqs-the-v0.4.0-headline}

For structures with two or more chemically-disordered sublattices
(rocksalt HEA-carbides, double perovskites, full Heusler with
independent X/Y/Z mixing, spinels), upstream SCRAPS had no API for
designing per-sublattice compositions --- \texttt{ELEMENT} is a single
flat species count over all positions and \texttt{randomizeLattice} did
a flat shuffle. The fork adds a \texttt{SUBLATTICE} INPUT keyword that
partitions basis positions and species into disjoint sublattices, with
every swap-proposal site gated so atoms only swap within a sublattice.

\begin{verbatim}
SUBLATTICE <id> BASIS <b1> <b2> ... SPECIES <s1> <s2> ...
\end{verbatim}

Disjoint species per sublattice means
\texttt{pairGr{[}i{]}{[}j{]}{[}shell{]}} and
\texttt{targetSROpair{[}i{]}{[}j{]}{[}shell{]}} need no new dimension
--- cross-sublattice pair counts (e.g.~metal--carbon nearest-neighbor in
HEA carbides) naturally fall in the right bins because species
\texttt{i} and \texttt{j} only live on one sublattice each.

INPUT-level validation in the parser (disjoint species, disjoint basis,
in-range, non-empty blocks); POSCAR-level validation in
\texttt{main.cpp} (BASIS bound, spectator-vs-sublattice conflict,
ELEMENT sum matches per-sublattice capacity, full basis coverage). When
no \texttt{SUBLATTICE} keyword is given, \texttt{main.cpp} synthesizes a
default single-sublattice spec covering all non-spectator basis
positions and species, so every downstream path (randomizeLattice, all
five swap-proposal sites, the targeted-swap residual scorer) uses one
uniform code path regardless of single- vs multi-sublattice mode --- no
\texttt{if/else} branching. The legacy
\texttt{SPECTATOR\_BASIS\_SPECIES} for fixed-species sublattices
continues to work alongside (and is, in effect, a special case of
``sublattice with one allowed species'').

Sublattice detection helper: \texttt{tools/sublattice\_detect.py} reads
a POSCAR via pymatgen, runs Wyckoff-orbit analysis (spglib under the
hood), and emits draft \texttt{SUBLATTICE} blocks with
\texttt{\textless{}fill\ in\textgreater{}} placeholders for SPECIES. Two
basis positions in the same Wyckoff orbit have identical
pair-correlation environments, so the orbit partition is the unique
coarsest partition that respects the lattice symmetry --- the right
default for multi-sublattice SQS. Users can override the auto-detected
partition by writing \texttt{SUBLATTICE} blocks by hand (e.g.~to break
symmetry intentionally).

Validated against rocksalt and Heusler L2₁ POSCARs:
\texttt{sublattice\_detect.py} reproduces the textbook orbit assignments
(NaCl \(\to\) 4a + 4b; Cu₂MnAl \(\to\) 4a Mn + 4b Al + 8c Cu).

\subsubsection{2.8 MPI singleton-mode
diagnosis}\label{mpi-singleton-mode-diagnosis}

The macOS-with-Homebrew-Open-MPI setup commonly fails to form a real
multi-rank communicator when \texttt{mpirun} from a different MPI
install (e.g.~anaconda's MPICH Hydra \texttt{mpirun}) is first on
\texttt{\$PATH}. Each process then runs as a singleton with rank 0 and
\texttt{nproc=1}, the 4 ``ranks'' do independent searches, and only
one's \texttt{SCRAPS.vasp} survives (the last to write).

Three coordinated fixes: 1. \textbf{C++ runtime detects the condition}
(\texttt{nproc==1} but
\texttt{\$OMPI\_COMM\_WORLD\_SIZE\ \textgreater{}\ 1}) and prints a loud
one-shot warning with the fix. 2. \textbf{\texttt{tools/tests} and
\texttt{tools/run\_sqs.py} auto-resolve} the matching \texttt{mpirun} by
looking next to the \texttt{mpic++} from \texttt{build.sh}
(\texttt{\$MPICXX}) before falling back to PATH. 3. \textbf{README
section} documenting the gotcha.

When real multi-rank can't be achieved, the conv-log path is suffixed
with the OS PID so concurrent singletons don't race-and- interleave
their writes (the test helper handles both modes).

\subsubsection{2.9 Opt-in higher-order figure
objective}\label{opt-in-higher-order-figure-objective}

\texttt{tools/higher\_order.py} uses icet 4.x to enumerate decorated
symmetry orbits, map their periodic figures to SCRAPs site order, and
export point-function values in the API's species order. Supported
figures have order 2--4, with one or more disordered sublattices and
optional fixed spectators. Shared species are supported with explicit
per-group integer counts in figure mode. Each local point function gets
a global basis row, with zero entries outside its allowed species set;
each term references the row appropriate to its site. Concentration
moments use the site's local species fractions. Symmetry enumeration
preserves declared sublattice identities, including groups with
identical allowed physical species. icet removes fixed-site constant
factors rather than introducing redundant chemical figures; fully fixed
sites remain present in the geometry and occupation constraints. The
exporter validates its explicit products against icet cluster vectors
before writing. Random-alloy targets are products of
concentration-weighted point-function moments; they are not assumed zero
and do not correct for finite-cell sampling without replacement.

\texttt{SCRAPs/FigureObjective.hpp} reads \texttt{FIGURES\_FILE} and
computes orbit averages. Each term stores a coefficient and
\texttt{(site,\ point-function)} factors; coefficients sum to one within
each decorated component. Periodic images that map to the same site
remain repeated factors, rather than being collapsed into a lower-order
cluster. A site-to-term incidence list enables swap updates. The union
of both sites' incidence lists visits shared terms once; rejected moves
leave accepted state untouched. Full recomputation refreshes the
incremental state every 1,024 proposals and at final scoring.

\texttt{main.cpp} routes every global fitness call and local search
kernel to this backend when enabled. It retains the native cuckoo
population/MPI gathering and the SA/PT acceptance and temperature
machinery. Compound moves compose swap updates before a joint decision;
\texttt{FAST\_SWAPS\ 0} supplies a full-evaluation reference.
\texttt{RNG\_SEED} seeds a separate reproducible figure-kernel stream. A
separate best-evaluated archive survives SA uphill moves and PT
exchanges without changing chain state. Figure-mode cuckoo proposals
accept improvements or numerical ties (1e-12), rather than applying the
legacy pair-count error band to normalized correlations. The legacy pair
path remains the default. Pair-specific \texttt{TARGETED\_SWAPS}, and
\texttt{SRO} fail clearly in figure mode. Swaps use the existing
same-sublattice site pools and skip fixed spectators. Randomization
preserves each local count. Legacy pair-coordination uniformity is not
required by the figure objective. The existing pair neighbor graph is
still built, but figure mode suppresses the legacy SRO diagnostic; use
\texttt{FIGURE\_CORRELATIONS.csv} for its actual targets.

The input controls are \texttt{FIGURES\_FILE},
\texttt{FIGURE\_OBJECTIVE} (\texttt{weighted\_l1} or \texttt{atat}),
\texttt{FIGURE\_WD} (default 0), \texttt{FIGURE\_WN} (default 1),
\texttt{FIGURE\_WR} (default 1), and \texttt{FIGURE\_TOL} (default
0.001). All are validated and known to the INPUT parser. In normalized
weighted-L1 mode, \(w_\alpha=\exp(-w_d d_\alpha/d_0)w_n^{n_\alpha-2}\)
applies to every decorated component, including pairs. One global
denominator preserves relative order penalties. No extra multiplicity
weighting or per-order normalization is applied. Geometric decay is a
prior for interaction importance, not a property-error guarantee.

\texttt{FIGURE\_CHECKPOINT\_SECONDS\ seconds} enables atomic per-rank
best-figure snapshots (\texttt{FIGURE\_CHECKPOINT.rankN.json}),
containing occupations, correlations and objective score. Default 0
disables output; positive finite values specify the minimum interval
between snapshots at proposal boundaries. Requires
\texttt{FIGURES\_FILE}. Snapshots preserve the search RNG and annealing
schedule; they are assessable structures, not restart state. Benchmark
readers must timestamp observation, including startup, and retain
snapshots observed before their deadline.

ATAT mode reproduces the 3.52 \texttt{calc\_objective\_func}
prescription: initialize one range per order to its largest included
diameter plus \(d_0\), truncate at the first mismatched diameter, cap
each higher-order range by the preceding order, and normalize residuals
over diameters at least the minimum range minus ATAT's
\texttt{zero\_tolerance=0.001}. Subtract
\(w_r\sum_{p=0}^{n_{max}-2}w_n^p R_p/d_0\) from this error.
Compatibility also retains ATAT's \texttt{-FLT\_MAX} sentinel when the
unnormalized weighted residual sum is below 0.001. This can arise
through very small weights despite unmatched correlations. Final
reporting therefore evaluates maximum residual independently;
negative/sentinel fitness never drives the old zero-error termination
check. Cutoff completeness and the icet point basis must also match
before comparing to an ATAT run: objective compatibility alone is not
identical feature-space compatibility.

The version-1 text format remains supported for unconstrained systems
and is whitespace-delimited (no comments):

Constrained exports use \texttt{SCRAPS\_FIGURES\ 2}. Immediately after
the basis matrix, version 2 inserts one row per site:
\texttt{N\_allowed\ species\_0\ ...}. The native reader checks these
allowed sets against the \texttt{SUBLATTICE} and
\texttt{SPECTATOR\_BASIS\_SPECIES} declarations after expanding the
lattice, and rejects version 1 for constrained systems. Python validates
full site/species coverage, disjoint basis sets and integer counts
against each group's capacity before export. The JSON additionally
records basis/site allowed sets and local basis moments. Explicit local
counts use format version 3. After the allowed-species rows, each site
has \texttt{group\_index\ count\_0\ ...\ count\_(TYP-1)}: active groups
use INPUT declaration order and their full local budget; fixed sites use
group \texttt{-1} and a one-hot occupation count. The native reader
checks this metadata against INPUT, rejecting stale targets after a
local-composition or partition change. For overlapping species the
exporter uses distinct auxiliary alphabets only during symmetry
enumeration, preserving physical atomic-number ordering within each
group. Exported occupations and structures use physical species. For
shared species, append \texttt{COUNTS\ n0\ n1\ ...} to every
\texttt{SUBLATTICE} line, aligned with its \texttt{SPECIES} list. These
local budgets plus fixed occupations must sum exactly to
\texttt{ELEMENT}. The Python API uses four-member tuples
\texttt{(id,\ basis\_positions,\ species\_indices,\ counts)}; CLI
partition JSON follows the same layout. The native optimizer initializes
and conserves each local budget. Without explicit counts,
disjoint-species behavior is retained. Legacy Warren--Cowley pair mode
rejects this extension because its pair reference arrays do not resolve
shared species by sublattice.

The C++ reader checks dimensions, finite values, indices, coefficient
normalization, presence of pairs, and consistency of the cell/site
ordering with POSCAR and \texttt{Cell\_DIM}. The exporter writes a
companion JSON containing provenance and feature metadata. Final
component correlations and native occupations are saved separately for
independent reconstruction. Performance and scientific superiority over
pair-only optimization remain to be measured.

\subsection{8. Release scope and remaining scientific
limitations}\label{release-scope-and-remaining-scientific-limitations}

The proposed release combines generation, structure analysis, worked
examples, checksummed external references and a bounded benchmark.
Publication of the repository, release and Zenodo archive requires the
author's final approval.

The benchmark has limited repetitions and does not establish broad
statistical superiority. Multi-component SRO inversion from ATAT
correlations remains a future extension; current independent SRO
fixtures cover binary equiatomic mixed sublattices. Structure mapping
accepts small displacements and atom reordering, with cell agreement
within 0.0001 angstrom for serialization rounding; it does not fit
arbitrary strain, rotations, origin shifts or vacancies. Prototype
examples do not establish phase stability or property accuracy.

\subsection{Submission benchmark}\label{submission-benchmark}

\texttt{tools/benchmark/submission/run.py} is the fixed four-method
comparison driver. It generates eight problems (two crystal families ×
two sizes × two target modes), runs every method on every problem, and
repeats the two smaller nonzero-target problems with a second seed: 40
trials at 30 s/four cores. \texttt{matched\_mcsqs.py} provides the ATAT
cluster mapping and independent audit; \texttt{icet\_extension.py}
retains icet 4.0's annealer with a shared ATAT score;
\texttt{sro\_targets.py} constructs realizable pair/triplet/quadruplet
targets. The saved realization is withheld from optimizer
initialization. Native checkpoint observation includes unfinished
annealing schedules. The driver freezes sources and inputs, resumes only
matching runs, and exports numerical regression fixtures. See README for
reproduction commands and timing limits.

\subsection{Evaluation of supplied
structures}\label{evaluation-of-supplied-structures}

\texttt{tools/structure\_analysis.py} implements
\texttt{m\_scraps\ analyze} and the public \texttt{analyze\_structure}
Python API. It maps structures to an explicit full-supercell reference,
counts ASE periodic neighbors by directed sublattice pair, and
normalizes Warren--Cowley SRO by the destination-sublattice
concentration. Coordination is conditioned on the center species, so
nonuniform coordination is reported rather than silently replaced by a
global average. Optional SRO targets produce residuals and aggregate
errors. Missing pairs remain undefined.

For supplied native figure files it reuses the independent Python
decorated correlation evaluator and benchmark metric definitions.
Species ordering, figure hash, basis, targets and weights accompany the
result. Mapping requires a unique bijection within the displacement
tolerance and equal cells; arbitrary strain, origin registration and
vacancy fitting are outside this interface. Tests include exact B2
ordering, sublattice normalization, fixed-site violations,
permuted/relaxed sites, and archived ATAT pair/triplet/quadruplet
correlations.

\texttt{m\_scraps\ compare-atat} supports offline golden-result
verification and optional live \texttt{corrdump} replay. The
\texttt{analysis\_oracle} fixtures retain raw external stdout, ATAT
inputs and checksums for three materials, with two configurations each.
Live replay also accepts a new decoration of a selected reference cell.
SRO checks use the documented binary-equiatomic inversion of ATAT pair
correlations; they do not relabel an internal SRO calculation as an
independent oracle.

\subsection{Completed submission
benchmark}\label{completed-submission-benchmark}

The frozen 40-trial campaign produced 40 validated outputs, with saved
ATAT oracle vectors and attainable-reference witnesses for nonzero
targets. The portable corpus is
\texttt{tools/fixtures/submission\_benchmark}; its manifest checks all
inputs and results. \texttt{m\_scraps\ benchmark\ -\/-report-only} reads
it without external engines; a short native rerun uses the same figure
definitions.

The \href{submission_benchmark.csv}{CSV} retains every trial, including
RMS and per-order errors. \href{submission_benchmark.png}{The figure}
