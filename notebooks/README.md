# m_scraps tutorial notebooks

Nine Jupyter notebooks cover generation, analysis and troubleshooting.
Notebooks 06–09 work from an installed package without ATAT or icet;
01–05 use the source checkout. Outputs are regenerated by execution. To re-run locally:

```bash
jupyter lab notebooks/<file>.ipynb
# or to execute all in-place and refresh outputs:
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=300 \
    notebooks/*.ipynb
```

To regenerate the `.ipynb` files from source (the markdown + code cells
for notebooks 01–05 are defined in `build_notebooks.py`; 06–09 are maintained directly):

```bash
python3 notebooks/build_notebooks.py
```

## Pick by use case

| You want to design ... | Open this notebook | What it shows |
|---|---|---|
| A single-sublattice SQS (e.g. NiCoCr 108-atom FCC) | **01_first_scraps_run.ipynb** | Shortest path from ASE `Atoms` to SQS supercell via `run_sqs_from_atoms`, with the `AUTO_BUDGET` keyword (no manual MC tuning), independent α verification, and 2D visualization. |
| A single-sublattice cell with **non-zero α targets** from literature (CSRO) | **02_targeting_csro.ipynb** | The `sro_targets=` parameter takes a list of `(species_i, species_j, shell, alpha)` tuples; one of the fork's headline features. |
| A high-entropy ceramic with one disordered metal sublattice and a fixed spectator (boride, carbide, oxide, ...) | **03_heb_end_to_end.ipynb** | `SPECTATOR_BASIS_SPECIES` workflow + the `suggest_cell.py` feasibility helper. Walks through (Hf,Zr,Ti,Ta,Nb)B₂. |
| Two or more chemically-disordered sublattices (rocksalt HEA-carbides, full Heusler, double perovskites, spinels, fluorite-type oxides, sigma/Laves phases) | **04_multi_sublattice.ipynb** | The `SUBLATTICE` keyword (v0.4.1+) and per-Wyckoff non-uniform-coordination (v0.4.2+). Walks through B2 (Ni,Co)(Ti,Zr) SQS + CSRO, then demonstrates `sublattice_detect.py` auto-detection on a Heusler L2₁ POSCAR. |
| To diagnose a failed or unexpected run | **05_troubleshooting.ipynb** | Five common failure modes with diagnoses: integer-feasibility floors, CSRO not hitting target, multi-sublattice uniformity errors, SCRAPS-vs-`verify_sro` discrepancies, and SCRAPS-vs-mcsqs disagreement. Reference material, not sequential. |
| Analyze existing diboride, MAX and Heusler structures | **06_structure_analysis.ipynb** | Composition, explicit sublattices and independent SRO checks. |
| Generate multi-sublattice structures | **07_generate_multisublattice.ipynb** | Bounded native generation followed by independent checks. |
| Small-cell error bounds, certified minima, and usable cell shapes | **08_small_cell_search.ipynb** | Single-sublattice BCC and multi-sublattice rocksalt; bound attainment versus exhaustion, geometry constraints, and tolerance screening. No ATAT/icet/native optimizer invocation. |
| Compare random and diverse ensembles | **09_configuration_ensembles.ipynb** | MAX-phase generation, exact targeted SRO, structure export, and frozen energy variability without an ML installation. |

## What you need to install

- `scraps` C++ binary at `SCRAPs/scraps` (run `./build.sh` from the
  repo root after installing MPI and Eigen).
- Python deps: `pip install -r tools/requirements.txt` (pymatgen,
  ASE, numpy, matplotlib, pytest).

## After running

Each notebook's `work_dir` (`nb1_first_run/`, `nb4_csro/`, etc.) is
gitignored — these are scratch run dirs that hold the POSCAR, INPUT,
SCRAPS.vasp output, and scraps.log for each run. Inspect them
directly to see what the wrapper wrote, or delete them between runs
for a clean slate.

## New materials workflows

- `06_structure_analysis.ipynb`: explicit mixed/fixed sublattices, independent
  composition validation and SRO for diboride, MAX-211 and Heusler prototypes.
- `07_generate_multisublattice.ipynb`: bounded native generation of the same
  three materials followed by independent structure/SRO checks.

These two notebooks store results in a fresh temporary directory printed at
the beginning. Prototype lattice parameters are illustrative, not stability
predictions. Package CI executes both outside the checkout.

## Small-cell design and certification

`08_small_cell_search.ipynb` uses features available in v0.6.0 and later. It executes against an installed
package outside the checkout, stores results in a fresh temporary directory,
and checks exported candidate errors independently. The new package-CI step
executes it alongside notebooks 06 and 07. Its limits are explicit: pair-SRO
only, per-cell certificates, and bounded coverage of cell sizes and shapes.

## Configuration ensembles and archived properties

`09_configuration_ensembles.ipynb` generates random and diversity-selected
32-atom MAX-phase ensembles from the same candidate pool, verifies composition
and targeted SRO, compares pair/triplet descriptor coverage, and exports both
ensembles. It then loads the frozen 32-structure MACE energy example, checks its
hashes and summary arithmetic, and plots energy variability without installing
MACE, MaterialsFramework, ATAT or icet. It makes no equilibrium-sampling claim.

Install from the checkout with `python -m pip install ".[notebooks]"` and select
that environment as the notebook kernel. Notebooks 08–09 invoke no native
optimizer, although building the package still requires MPI and Eigen. Tutorial
09 runs outside the checkout with an installed wheel and stores all new outputs
in a temporary directory. It is included in the existing release/manual package
check; no additional routine or scheduled CI workflow is introduced.
